Por qué pedimos esto

Ya probamos SMTP clásico contra smtp.office365.com y falla en dos formas distintas: primero 535 5.7.139 ... disabled for the Tenant (SMTP AUTH apagado para todo M365 del ITM), y luego, con esta cuenta, un error de credenciales que probablemente sea Conditional Access bloqueando autenticación heredada.

En cambio, confirmamos que Microsoft Graph sí funciona contra este tenant (probado con un login interactivo). Por eso pedimos la vía de aplicación — sin que ningún usuario tenga que iniciar sesión — en lugar de seguir insistiendo con SMTP.

01Qué necesitamos

Un App Registration en Entra ID que nuestro backend use para enviar correo por Graph de forma desatendida: el sistema corre solo, sin ningún humano presente, y manda el correo automáticamente cuando alguien crea o gestiona una reserva.

02Pasos

  1. Crear el App Registration en Entra ID — nombre sugerido reservas-parquei-mail.
  2. Agregar el permiso Microsoft Graph → API permissions → Application permissions → Mail.Send. De aplicación, no delegado.
  3. Dar consentimiento de administrador a ese permiso.
  4. Generar un client secret (o certificado, si prefieren esa vía) y anotar su fecha de vencimiento.
  5. Restringir el alcance con una ApplicationAccessPolicy de Exchange Online, para que esta app solo pueda enviar como sgc-lia@itm.edu.co — no como cualquier buzón del tenant.
PowerShell · Exchange Online · paso 5 
# Una vez tengan el Application (client) ID del paso 1
New-ApplicationAccessPolicy `
  -AppId "<Application (client) ID>" `
  -PolicyScopeGroupId "sgc-lia@itm.edu.co" `
  -AccessRight RestrictAccess `
  -Description "reservas-parquei-mail solo envia como sgc-lia@itm.edu.co"

03Qué necesitamos de vuelta

Cuatro valores, el mismo formato que usa cualquier .env de este tipo de integración:

AZURE_TENANT_ID
Directory (tenant) ID del ITM en Entra ID.
AZURE_CLIENT_ID
Application (client) ID del App Registration del paso 1.
AZURE_CLIENT_SECRET
El valor del secret generado en el paso 4 — no el ID del secret, el valor mismo.
SECRET_EXPIRES
Fecha de vencimiento, para saber cuándo hay que renovarlo.
Atención al entregarlo El client secret es una credencial sensible, igual que una contraseña. Pedimos que se entregue por un canal seguro — un gestor de contraseñas compartido o en persona — nunca en el cuerpo de un correo ni en un ticket visible para cualquiera con acceso al sistema.

04Si esto no es posible

Alternativa de respaldo: la excepción puntual de SMTP AUTH sobre este mismo buzón.

PowerShell · Exchange Online · alternativa 
Set-CASMailbox -Identity "sgc-lia@itm.edu.co" `
  -SmtpClientAuthenticationDisabled $false
Pero ojo Habría que confirmar también que ninguna política de Conditional Access esté bloqueando "Authenticated SMTP" para esta cuenta — ya lo probamos una vez y el error sugiere que hay algo más, además del toggle del buzón, bloqueando la conexión.
