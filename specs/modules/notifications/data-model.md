# Modelo de datos — Notifications

## Fuente y alcance

Definiciones extraídas del [modelo principal](../../docs/data-model.md). Se conservan los campos, tipos, restricciones y observaciones de las tablas asignadas al módulo. Esta documentación no aplica cambios en la base de datos.

Convenciones: `PK` clave primaria; `FK` clave foránea; `UQ` único; `NN` `NOT NULL`; `Sí` admite `NULL`. Las FK sin acción explícita usan `NO ACTION`. Según el principal, las identidades de tablas de `reservas` son `GENERATED BY DEFAULT AS IDENTITY`; cargos y personal usan `GENERATED ALWAYS`.

## Tablas

### `reservas.notificaciones`

| Campo | Tipo | Null | PK/UQ/FK/default/check |
|---|---|---|---|
| `id` | integer | NN | PK `notificaciones_pkey`; identity |
| `usuario_id` | integer | NN | Sin FK declarada |
| `reserva_id` | integer | Sí | FK → `reservas.reservas(id)` ON DELETE CASCADE |
| `tipo` | varchar(20) | NN | CHECK `PENDIENTE`, `APROBADA`, `RECHAZADA`, `CANCELADA` |
| `leida` | boolean | NN | DEFAULT `false` |
| `created_at` | timestamptz | NN | DEFAULT `now()` |

Índice `ix_notificaciones_usuario(usuario_id, leida)`.

## Relaciones y diferencias pendientes

La definición procede del principal, aunque la tabla esté en el schema `reservas`. El destinatario documentado es `usuario_id integer` sin FK: no coincide con `usuarios.usuarios.id_usuario bigint` ni identifica explícitamente una cuenta de `auth.cuentas`. Debe resolverse su referencia conforme a las reglas de destinatarios antes de implementar el modelo objetivo.

El CHECK de `tipo` solo contiene cuatro valores ligados al ciclo anterior de reservas. Las reglas del módulo contemplan más eventos y canales; sus estructuras de entrega, contenido y control de duplicados aún no están definidas en el principal.

El `ON DELETE CASCADE` de `reserva_id` elimina las notificaciones si se borra la reserva. Debe conciliarse con la conservación histórica exigida por el módulo. Se conserva la restricción del inventario sin afirmar que satisface las reglas objetivo.

El estado oficial de la reserva pertenece a [Reservations](../reservations/data-model.md); el estado de lectura de una notificación no lo modifica.
