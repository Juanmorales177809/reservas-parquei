# Modelo de datos — Espacios

## Fuente y alcance

Definiciones extraídas del [modelo principal](../../docs/data-model.md). Se conservan los campos, tipos, restricciones y observaciones de las tablas asignadas al módulo. Esta documentación no aplica cambios en la base de datos.

Convenciones: `PK` clave primaria; `FK` clave foránea; `UQ` único; `NN` `NOT NULL`; `Sí` admite `NULL`. Las FK sin acción explícita usan `NO ACTION`. Según el principal, las identidades de tablas de `reservas` son `GENERATED BY DEFAULT AS IDENTITY`; cargos y personal usan `GENERATED ALWAYS`.

## Tablas

### `reservas.espacios`

| Campo | Tipo | Null | PK/UQ/FK/default/check |
|---|---|---|---|
| `id` | integer | NN | PK `espacios_pkey`; identity |
| `id_unidad` | integer | NN | FK `espacios_id_unidad_fkey` → unidad organizacional |
| `nombre` | varchar(100) | NN | UQ compuesta `uq_espacios_unidad_nombre` con `id_unidad` |
| `ubicacion` | varchar(255) | Sí | — |
| `capacidad` | integer | NN | CHECK `> 0` |
| `descripcion` | text | Sí | — |
| `habilitado` | boolean | NN | DEFAULT `true` |

## Relaciones y responsabilidad

Espacios es propietario funcional de `reservas.espacios`, conforme a sus [reglas RN-ESP](busines-rules.md). La pertenencia física al schema `reservas` no cambia esta responsabilidad. El overview previo de Resources agrupa espacios y recursos; para el detalle persistente, la definición de espacios se centraliza aquí y Resources la referencia.

Cada espacio pertenece a una unidad de [Administration](../administration/data-model.md). La configuración del laboratorio está en [Resources](../resources/data-model.md); las reservas referencian el espacio desde su cabecera en el inventario y desde `reserva_espacio` en el [diseño objetivo](../reservations/data-model.md).

## Estructuras pendientes

El principal aún no define las tablas de asociación espacio–recurso, campos adicionales ni opciones exigidas por RN-ESP-REC y RN-ESP-CAM. Sus PK, FK, orden, tipos y reglas de conservación deben especificarse antes de implementar. `reserva_campos_valores` depende de este diseño.

RN-ESP-02 contempla capacidad cuando aplique, pero el inventario exige capacidad `NOT NULL` y mayor que cero. Se conserva la definición del principal y queda pendiente conciliar esta diferencia.
